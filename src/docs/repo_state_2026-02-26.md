# Анализ текущего состояния репозитория (2026-02-26)

## 1) Что сейчас в репозитории

- Репозиторий очень компактный: один `README.md` и три SCAD-реализации в `src/original`, `src/chatgpt`, `src/codex`.
- `README.md` пока содержит только заголовок проекта без описания запуска, архитектуры и плана развития.
- В `src/docs` уже есть предыдущие аналитические отчёты (`report_0.md`, `report_1.md`) и формулировка технического задания (`readme_prompt.md`).

## 2) Состояние кода по версиям

### `src/original/helical_antenna.scad`
- Историческая/внешняя версия, завязанная на внешние библиотеки через `use <dot/...>`.
- Без этих зависимостей файл не является самодостаточным для воспроизводимой сборки.

### `src/chatgpt/helical_antenna_v11.scad`
- Более зрелая параметрическая версия, но видны риски по архитектуре и стабильности:
  - смешение расчётов, UI и геометрии в одном файле;
  - высокая сложность рендера из-за спирали на `hull()` сегментов;
  - часть поведения для экспортных режимов нуждается в формализации под batch-экспорт.

### `src/codex/helical_antenna_v0.scad`
- Наиболее системно оформленная версия под промышленное ТЗ:
  - явные модули (`full_helix`, `body_section`, `hub`, `reflector`, `bracket`, `assembly`),
  - проверки через `assert()`,
  - консольные `echo()` ключевых размеров,
  - разделение режимов вывода.
- Это лучший кандидат на роль базовой main-ветки разработки.

## 3) Главные риски проекта

1. **Нет единой «канонической» версии.** Сейчас одновременно живут 3 SCAD-подхода, что повышает стоимость сопровождения.
2. **Недостаток документации для пользователя/разработчика.** Невозможно быстро понять: какую версию запускать, какие параметры считать стабильными, как экспортировать STL по секциям.
3. **Нет автоматической проверки (CI).** Нет гарантии, что изменения не ломают рендер (F6/CGAL) и не меняют ключевые расчётные размеры.
4. **Нет структуры артефактов.** Не определено, куда складывать экспортные STL, превью-рендеры и референсные параметры.

## 4) Рекомендуемые дальнейшие действия

### Приоритет P0 (сделать в первую очередь)

1. **Назначить основную реализацию**
   - Принять `src/codex/helical_antenna_v0.scad` как основной файл разработки.
   - Остальные версии пометить как `legacy` или `reference`.

2. **Нормализовать структуру репозитория**
   - Предложение:
     - `src/main/helical_antenna.scad` — активная версия,
     - `src/legacy/` — исторические варианты,
     - `examples/params/*.json` — наборы параметров для типовых частот,
     - `artifacts/` — экспорт STL/PNG.

3. **Минимально заполнить README**
   - Что это за проект,
   - какую SCAD-версию использовать,
   - как запускать preview/export через OpenSCAD CLI,
   - какие ограничения текущей версии.

### Приоритет P1 (следующим этапом)

4. **Добавить базовый CI-пайплайн**
   - Проверка синтаксиса и dry-run генерации,
   - рендер хотя бы одной тестовой конфигурации,
   - контроль наличия ключевых `echo()` параметров.

5. **Ввести baseline-набор параметров**
   - Например: 1200/2400/5800 MHz,
   - сохранить эталонные значения `turns`, `rod_length`, `reflector_diameter` для регрессии.

6. **Формализовать экспортные режимы**
   - Явно определить: чем отличаются preview/single/sequence,
   - добавить инструкцию пакетного экспорта секций для печати.

### Приоритет P2 (улучшение качества)

7. **Оптимизация геометрии спирали**
   - Рассмотреть замену части `hull()`-логики на более лёгкий подход, если визуально и технологически приемлемо.

8. **Усилить инженерные проверки**
   - Дополнительные `assert()` на диапазоны параметров,
   - явные комментарии по единицам измерения и допускам печати.

## 5) Предложенный краткий roadmap (2 недели)

- **День 1–2:** выбор main SCAD + реорганизация папок.
- **День 3–4:** обновление README и запускных команд.
- **День 5–7:** CI + smoke-тест параметров.
- **Неделя 2:** оптимизации спирали и стабилизация экспортных режимов.

## 6) Критерии готовности следующего этапа

- Один официальный SCAD-файл в статусе production-ready.
- Понятная инструкция запуска и экспорта в README.
- Автоматическая проверка сборки в CI.
- Повторяемый экспорт секций/деталей в стандартизированную структуру.
